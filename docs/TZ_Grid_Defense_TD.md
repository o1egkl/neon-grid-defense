# Техническое задание (ТЗ) и дизайн-документ: *Neon Grid Defense* (Tower Defense)

## 1. Общие сведения и концепция

### 1.1. Идея проекта
**Neon Grid Defense** — тактическая игра в жанре Tower Defense с механикой **mazing** (построения лабиринтов на открытой сетке), вдохновлённая классикой [Defense Grid: The Awakening](https://store.steampowered.com/app/18500/Defense_Grid_The_Awakening/) и минималистичным подходом [Grid Defense](https://store.epicgames.com/p/grid-defense-f1342f).

Ключевая особенность: игрок не просто расставляет башни вдоль готовой дороги, а сам формирует маршрут врагов на сетке, балансируя между удлинением пути, концентрацией огневой мощи и экономикой накопления.

### 1.2. Целевые платформы
* **Основная (MVP):** Web (десктопный и мобильный браузер), Windows.
* **Целевая (Release):** Android (APK/AAB), Web (HTML5), Windows.

## 2. Геймдизайн (Game Design Document)

### 2.1. Визуальный стиль и UX-иерархия
* **Сеттинг:** «Тактический кибер-грид» (Minimalist Sci-Fi / Neon Vector).
* **Палитра:**
  * Фон поля: глубокий тёмно-синий / графитовый (`#0B0F17`), линии сетки (`#1C2538`).
  * Траектория пути (Path Preview): пульсирующая полупрозрачная линия (`#00E5FF`).
  * Зоны запрета / ошибки (блокировка пути): контрастный красный (`#FF3B5C`).
  * Башни и враги: чёткая геометрическая дифференциация по силуэту и цвету роли (кинетика — синий, AoE — оранжевый, замедление — голубой, энергия/щиты — фиолетовый, снайпер — золотой).
* **Читаемость:** камера `Top-Down` (или лёгкая изометрия 2.5D без искажения кликабельности клеток). Полосы здоровья и щитов врагов отображаются только при получении урона или наличии щита.

### 2.2. Основной игровой цикл (Core Loop)
1. **Фаза планирования:** игрок изучает точки входа (`Spawn`), ядро (`Core Hub`) и преграды на сетке.
2. **Строительство и Mazing:** установка башен удлиняет маршрут врагов. При наведении курсора/пальца на клетку отображается предпросмотр нового пути в реальном времени.
3. **Волна и бой:** враги движутся по рассчитанному пути. Башни автоматически атакуют цели согласно выбранному приоритету.
4. **Экономика и адаптация:** за убийства начисляются кредиты; в конце волны начисляется процент (Interest) на неиспользованный остаток. Игрок улучшает ключевые башни, продаёт временные блокеры и перестраивает лабиринт под новые типы угроз (например, летающих врагов).

### 2.3. Уникальные механики (в стиле Grid / Defense Grid)
* **Система энергетических ядер (Energy Cores):** на базе хранится 10 ядер. Дошедший до базы враг не исчезает мгновенно, а забирает 1 ядро и идёт с ним обратно к выходу. Если убить носителя до выхода, ядро медленно летит обратно к базе (по пути его может подобрать другой враг). Поражение наступает только при уносе всех ядер.
* **Процентный доход (Interest):** по завершении каждой волны игрок получает бонус `+5%` (или `+10%` при сохранности всех ядер) от текущего баланса кредитов.
* **Тактическая пауза и скорость:** переключение скорости `1x / 2x / 3x` и активная пауза с возможностью строить, продавать и улучшать башни.

### 2.4. Арсенал башен (6 базовых типов)
Каждая башня имеет 3 уровня прокачки; на 3-м уровне доступна **специализация** (выбор одной из двух веток):

| Башня | Роль | Тип урона | Особенность / Специализация на ур. 3 |
| :--- | :--- | :--- | :--- |
| **Pulse** | Блокер / ДПС | Кинетический (соло) | Низкая цена для построения лабиринта. Ветки: *Rapid Gatling* (скорострельность) / *Heavy Rounds* (криты). |
| **Cannon** | Толпа (AoE) | Взрывной (сплэш) | Средняя дальность, урон по площади. Ветки: *Cluster Shell* (доп. осколки) / *Siege Mortar* (дальность + стан). |
| **Cryo** | Контроль | Замедление + урон | Снижает скорость врагов в радиусе на 30–50%. Ветки: *Permafrost* (сильное замедление) / *Brittle* (+20% входящего урона). |
| **Tesla** | Анти-щит | Электрический | Цепная молния (3–5 целей), повышенный урон по щитам. Ветки: *Overload* (макс. целей) / *EMP* (сброс способностей). |
| **Laser** | Анти-броня | Термальный луч | Непрерывный луч, урон растёт каждую секунду удержания цели. Ветки: *Focus Beam* (соло-босс) / *Prism Split* (2 луча). |
| **Railgun** | Снайпер | Бронебойный | Огромная дальность, игнорирует броню, низкая скорострельность. Ветки: *Pierce* (пробивает линию) / *Executioner* (урон по лоу-ХП). |

### 2.5. Архетипы врагов (7 типов)
1. **Swarm:** низкое HP, высокая скорость, идут плотными группами.
2. **Trooper:** базовый сбалансированный юнит.
3. **Armored Tank:** высокое HP, снижение входящего физического урона (контрится Laser/Railgun).
4. **Shielded:** энергетический щит поверх HP, быстро регенерирует вне боя (контрится Tesla).
5. **Medic:** периодически лечит союзников в небольшом радиусе.
6. **Splitter:** после смерти распадается на 2–3 юнита Swarm.
7. **Drone (Flying):** игнорирует стены лабиринта, летит по прямой к ядру (требует ПВО-покрытия по всей карте).

## 3. Стек технологий (Tech Stack)

Выбор стека оптимизирован под кросс-платформенную разработку (Web + Android + Windows), высокую производительность при расчёте сеток и быструю итерацию.

### Вариант А — Рекомендуемый: **Godot 4.3+ (GDScript)**
* **Движок:** Godot Engine 4.3+ (рендерер `Compatibility` / GLES3 для максимальной совместимости с WebGL2 и мобильными GPU).
* **Поиск пути:** нативный `AStarGrid2D` (написан на C++, пересчитывает сетку 32×24 за доли миллисекунды).
* **Визуал и эффекты:** 2D/2.5D сцены, `WorldEnvironment` (Glow/Bloom), `GPUParticles2D` / `MultiMeshInstance2D` для массовых снарядов.
* **Данные и баланс:** JSON-конфиги или кастомные `Resource` (`.tres`).
* **CI/CD и деплой:** GitHub Actions — автосборка Web-демо (GitHub Pages), Android (APK/AAB) и Windows (`.exe`) из одного репозитория.

### Вариант Б — Альтернатива (Web-first): **TypeScript + PixiJS v8 (или Three.js) + Vite**
* **Рендер:** PixiJS v8 (WebGL2/WebGPU 2D с отличным батчингом спрайтов и шейдеров) либо Three.js для 2.5D/3D-сетки.
* **Поиск пути:** кастомный **Flow Field** (BFS/Dijkstra на `Uint16Array`) или `easystarjs` с кэшированием.
* **Деплой:** Vercel / GitHub Pages для Web + Capacitor / TWA для упаковки в Android.

| Критерий | Godot 4 (Рекомендуемый) | TypeScript + PixiJS / Three.js |
| :--- | :--- | :--- |
| Скорость разработки прототипа | Очень высокая (встроенные `AStarGrid2D`, UI, таймеры, пулы) | Средняя (UI и pathfinding нужно собирать вручную) |
| Производительность Web | Хорошая (WASM, ~15–20 МБ билд) | Максимальная (нативный JS, ~1–2 МБ билд, мгновенный старт) |
| Сборка под Android / Windows | Нативная из коробки + CI/CD | Требует обёртки (Capacitor / Electron) |
| Поддержка AI-ассистентов (Cursor/Cline) | Отличная для GDScript и JSON | Отличная для TypeScript |

## 4. Техническое задание (ТЗ)

### 4.1. Архитектура и основные модули
Проект строится по модульному принципу с разделением логики симуляции и представления:
1. **`GridManager`:** хранит двумерный массив состояния клеток (`EMPTY`, `WALL`, `SPAWN`, `CORE`, `TOWER`, `HIGHLIGHT`). Отвечает за конвертацию мировых координат в координаты сетки и обратно.
2. **`PathfindingService`:** обёртка над `AStarGrid2D` (или Flow Field).
   * Метод `can_place_tower(cell) -> bool`: временно блокирует клетку и проверяет наличие валидного пути от **каждого** активного `Spawn` до `Core` и обратно (для механики возврата ядер), а также проверяет, не заперт ли ни один живой враг на карте.
   * Метод `recalculate_paths()`: обновляет маршруты и рассылает сигнал `path_updated` для перерисовки линии предпросмотра.
3. **`WaveManager`:** читает сценарий волн уровня, управляет спавном с интервалами, запускает следующую волну досрочно (с бонусным золотом за ранний вызов) и отслеживает условие победы/поражения.
4. **`TowerController`:** управляет состояниями башни (поиск цели по приоритету: `FIRST`, `LAST`, `STRONGEST`, `CLOSEST`, `CARRIER`), перезарядкой, апгрейдом, специализацией и продажей (возврат 75% вложенных кредитов).
5. **`ProjectileAndEffectPool`:** пул объектов (Object Pooling) для снарядов, лучей, частиц и всплывающих чисел урона (zero-allocation в игровом цикле).
6. **`EconomyManager`:** баланс кредитов, начисление за убийства, расчёт процентов (`Interest`) в конце волны, учёт количества сохранённых ядер.
7. **`SaveManager`:** сохранение прогресса кампании, звёзд/рекордов по уровням и настроек звука/локализации (`EN` / `RU`) в `user://save.json` (или `localStorage` для Web).

### 4.2. Функциональные требования к интерфейсу (UI/UX)
* **Главное меню:** выбор уровня (карта кампании), режим Endless, настройки (громкость SFX/Music, язык RU/EN, переключение качества графики).
* **Игровой HUD:**
  * Верхняя панель: Кредиты (`Gold`), Ядра (`Cores: 10/10`), Текущая волна (`Wave 3/20`), Счёт (`Score`), Кнопки скорости (`Pause`, `1x`, `2x`, `3x`).
  * Нижняя/боковая панель строительства: 6 иконок башен с ценой и горячими клавишами (`1`–`6`).
  * Контекстное меню выбранной башни: отображение радиуса, текущего ДПС, переключатель приоритета цели, кнопки `Upgrade` (с предпросмотром прироста статов) и `Sell`.
* **Управление:**
  * Десктоп: ЛКМ — выбор/установка башни, ПКМ или `Esc` — отмена выбора/снятие выделения, `Space` — пауза.
  * Тачскрин (Android/Mobile Web): тап по клетке открывает радиальное меню или подсвечивает предпросмотр установки с кнопкой подтверждения (защита от случайных кликов пальцем).

### 4.3. Схема данных (Data-Driven конфиги)
Баланс выносится в JSON-файлы, не зашитые в код:
* `towers.json`: `id`, `name`, `cost`, `range`, `fire_rate`, `damage`, `damage_type`, `aoe_radius`, `slow_factor`, `upgrades[]`, `specializations[]`.
* `enemies.json`: `id`, `hp`, `shield`, `armor`, `speed`, `bounty`, `is_flying`, `abilities[]`.
* `levels/level_01.json`: `grid_size: [24, 16]`, `start_gold`, `cores_count`, `spawns[]`, `core_pos`, `obstacles[]`, `waves[]`.

### 4.4. Нефункциональные требования и производительность
* Стабильные **60 FPS** на мобильных устройствах среднего класса и в WebGL2 при одновременном нахождении на карте до **150 врагов** и **60 башен**.
* Запрет на динамическое создание/удаление тяжёлых нод в основном цикле боя — обязательное использование пула объектов для снарядов и VFX.
* Защита от случайного скролла/зума страницы в мобильном браузере и корректная пауза при сворачивании вкладки (`visibilitychange` / `NOTIFICATION_APPLICATION_PAUSED`).

## 5. Этапы разработки (Milestones)

1. **Milestone 1 — Core Prototype (Играбельный «серый» прототип):**
   * Сетка, размещение башен-блокеров, `PathfindingService` с валидацией блокировки пути и предпросмотром траектории.
   * 1 тип врагов, 2 типа башен (Pulse, Cannon), базовый спавнер волн.
2. **Milestone 2 — Полная механика и контент:**
   * Внедрение системы **Energy Cores** (кража и возврат ядер) и экономики **Interest**.
   * Реализация всех 6 башен (включая специализации) и 7 типов врагов (включая летающих и щиты).
   * Загрузка уровней и волн из JSON.
3. **Milestone 3 — Визуал, UI/UX и «Сочность» (Juice):**
   * Неоновые шейдеры, эффекты выстрелов/взрывов, всплывающий урон, звуковое сопровождение.
   * Полноценный HUD, контекстные меню, туториал на 1-м уровне, локализация (RU/EN).
4. **Milestone 4 — Балансировка, оптимизация и CI/CD:**
   * Подготовка 15–20 уровней кампании + Endless Mode.
   * Настройка Object Pooling и профилирование на Web/Android.
   * Настройка GitHub Actions для автоматической сборки Web, Windows и Android (APK/AAB).
